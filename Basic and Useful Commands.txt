git romote -v (查看当前配置，fetch地址和push地址)
git remote set-url --push origin XXXXXXXXXX (单独设置push地址)
去掉--push就会同时覆盖fetch和push地址，这个操作适用于你fork了别人的仓库后，往你fork后的仓库进行推送。
fetch地址对应：git clone/git fetch/git pull
push地址对应：git push

git pull 直接拉取远程新的提交，并覆盖成远程文件内容
git fetch 把所有新的提交及分析镜像下载下来，但不合并代码
安全操作是：
git fetch origin
git diff origin/main
git merge origin/main

PR合并后，同步原仓库更新到网上的Fork仓库
1.把上游仓库添加到本地
git remote add upstream https://github.com/原作者账号/仓库名.git
验证是否添加成功
git remote -v
会看到两个远程origin:我的fork仓库，upstream:原作者上游仓库
如果已添加过upstream不要再重复git remote add，会报重复错误
2.拉取上游仓库最新代码
git fetch upstream --prune
执行完，本地就有了上游main分支的镜像
3.切换到本地main主分支
git checkout main
4.把上游main合并到本地main
git merge upstream/main
5.把合并后的最新代码推送到自己的Fork仓库
git push origin main

配置PAT令牌：
继续使用 HTTPS（当前的 remote 地址，最简单，不用改仓库配置）
1. 浏览器登录 Github，去创建个人访问令牌 PAT
Settings → Developer settings → Personal access tokens → Tokens (classic)
   - 勾选权限：`repo`（仓库读写权限）
   - 生成令牌，**复制保存好，只显示这一次！**
2. 当 Git 弹出登录窗口：
   - Username：你的 GitHub 用户名（Peak568）
   - Password：粘贴刚才生成的 PAT 令牌
3. 认证成功后，即可正常 push。
> 如果 Windows Git 凭据管理器记住了旧的错误凭据，会反复 401，需要清理：> Windows 搜索「凭据管理器」→ Windows 凭据，找到[github.com](https://github.com)条目，删除。下次 push 会重新弹窗输入。
